Unidad 2: Modelado y Diseño

En esta unidad aprenderás a representar visualmente un sistema antes de programarlo. Así como un arquitecto usa planos antes de construir una casa, un programador puede usar diagramas para planear clases, objetos, relaciones y procesos.

Trabajaremos principalmente con UML, que significa Lenguaje Unificado de Modelado. UML permite explicar cómo se organiza un programa sin depender todavía de un lenguaje como Java, Python o C++.

  • Identificarás elementos básicos de un diagrama de clases.
  • Relacionarás símbolos UML con su significado.
  • Comprenderás el orden de mensajes en diagramas de secuencia.
  • Distinguirás relaciones como asociación, herencia, agregación y composición.

2.1 ¿Qué es UML?

UML es una forma estándar de representar visualmente un sistema. Sirve para planear, comunicar y documentar cómo estará organizado un programa.

En Programación Orientada a Objetos, UML ayuda a responder preguntas como:

  • ¿Qué clases necesita mi sistema?
  • ¿Qué datos tendrá cada clase?
  • ¿Qué acciones podrá realizar?
  • ¿Cómo se comunican los objetos entre sí?
Ejemplo: Para un sistema escolar podrías modelar clases como Alumno, Profesor, Materia y Calificacion antes de escribir código.

2.2 Diagrama de clases

El diagrama de clases muestra la estructura de un sistema. Representa las clases, sus atributos, sus métodos y las relaciones que existen entre ellas.

Una clase en UML se dibuja como un rectángulo dividido en tres partes:

Parte Contenido Ejemplo
Nombre Nombre de la clase Estudiante
Atributos Datos o características - nombre : String
Métodos Acciones o comportamientos + estudiar() : void

2.3 Visibilidad en UML

En UML se usan símbolos para indicar qué tan accesible es un atributo o método.

Símbolo Nombre Significado
+ public Puede accederse desde otras clases.
- private Solo puede usarse dentro de la misma clase.
# protected Puede usarse en la clase y sus hijas.

2.4 Diagrama de secuencia

El diagrama de secuencia muestra cómo interactúan los objetos durante un proceso. A diferencia del diagrama de clases, este se enfoca en el comportamiento y en el orden de los mensajes.

  • Actor: persona o sistema que inicia una acción.
  • Objeto: elemento que participa en la interacción.
  • Línea de vida: línea vertical que representa la existencia del objeto durante el proceso.
  • Mensaje: flecha que indica comunicación entre objetos.
  • Foco de control: rectángulo delgado que indica que el objeto está ejecutando una acción.

2.5 Relaciones UML

Las relaciones muestran cómo se conectan las clases entre sí. Estas conexiones ayudan a entender la estructura del sistema.

Relación Idea principal Ejemplo
Asociación Una clase se relaciona con otra. Profesor enseña Materia
Herencia Una clase hija hereda de una clase padre. Perro hereda de Animal
Agregación Relación parte-todo débil. Equipo tiene Jugadores
Composición Relación parte-todo fuerte. Casa tiene Habitaciones
